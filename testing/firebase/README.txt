Проверка Firebase без доступа к рабочим данным

Тесты используют только demo-shared-organizer и локальный Firestore Emulator на 127.0.0.1:8080.
Они не читают google-services.json и не требуют аккаунтов или паролей реальных участников.
KOTIKI_FIREBASE_TOOLS — внешний каталог установки npm-зависимостей Firebase.
JAVA_HOME — JDK 21; Node 24 и java должны быть в PATH.
FIREBASE_EMULATORS_PATH — внешний каталог хранения образов эмулятора.

Из корня репозитория:
firebase emulators:exec --only firestore --project demo-shared-organizer --config firebase.json "node --test --test-concurrency=1 testing/firebase/rules.test.cjs"

23 сценария: отказ анониму/постороннему, запрет самостоятельного вступления и подмены владельца, общие/личные записи, безопасная занятость, отзыв доступа к истории, readonly, изменение разрешений, подтверждение приглашений, атомарная история, неизменяемость версий, удаление/восстановление, конфликт офлайн, личные списки и отзыв членства; временное делегирование роли и его истечение; общий чат, авторство, удаление своих сообщений; чат активного отдельного плана; отмена удаления принятого приглашения.

Дополнительно CloudStoreTest проверяет отсутствие импорта демоданных, отсутствие повторной отправки полученных снимков, редактирование локального облачного состояния, безопасные проекции и права удаления приглашений.

Ручной сценарий на Android: войти → создать дело → проверить после перезапуска; выйти после синхронизации → войти вторым аккаунтом → увидеть общее дело и не увидеть личное; личная запись с занятостью показывает только расписание. Отключить сеть → изменить → закрыть/открыть → подключить сеть → проверить статус и историю. Не заменять этой проверкой тесты Firestore Rules.
Личные отчёты, снимки и логи помещать в testing/local/firebase/.

Изолированные тестовые аккаунты
Эмуляторы используют только синтетические данные в отдельном тестовом пространстве.
Запрещены реальные пользовательские записи, личные пресеты и делегирование реальной
роли. Старые grant-delegates/renew-delegates не применять для эмуляторных тестов.
У каждой тестовой identity canonicalUid совпадает с её собственным UID; членство
и пространство имеют testOnly=true. До UI-теста подтвердить серверный отказ чтения
и записи в реальные пространства. У приложения отдельный пакет team.kotiki.app.agents.
Конфигурация и отчёты только в ignored testing/local/; секреты не публиковать.
KOTIKI_AGENT_ASSETS содержит только локальную конфигурацию Firebase тестового пакета.
KOTIKI_TEST_ASSETS и KOTIKI_MIGRATION_ASSETS в эмуляторную сборку не включать.
