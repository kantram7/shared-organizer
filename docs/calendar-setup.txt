Подключение календарей — односторонние копии

Интеграция в приложении
- CalendarExportActions(entry, authUid) показывать только для сохранённой записи и актуального вошедшего пользователя. В редакторе при несохранённых правках сначала предложить сохранение.
- CalendarConnectionSettings(authUid) вставить в прокручиваемые настройки.
- Зависимости: com.google.android.gms:play-services-auth:22.0.0; com.squareup.okhttp3:okhttp:4.12.0. INTERNET уже объявлен. Разрешение Android READ/WRITE_CALENDAR не требуется.
- Нажатие Google/Яндекс создаёт копию, следующее «Изменить в календаре» обновляет тот же внешний ID. События не импортируются обратно. Удаление в организаторе не удаляет внешнюю копию. Участники не отправляются в качестве email-attendees: внешние приглашения не рассылаются.
- Даты без времени передаются как all-day, окончание — следующий день после включительной последней даты. Для времени используется выбранный часовой пояс (устройство по умолчанию, можно выбрать Europe/Moscow). CalDAV получает эквивалентные UTC-моменты, без floating time. Неоднозначное время при переходе DST требует исправления.

Что должен настроить владелец для Google
1. В Google Cloud проекте включить Google Calendar API.
2. Настроить OAuth consent screen/Google Auth Platform (название, поддержка, сведения о приложении); при Testing добавить нужные Google аккаунты в Test users. OAuth в Testing может требовать повторного согласия; доступ и ограничения зависят от статуса consent screen.
3. Создать OAuth client типа Android для фактического applicationId и SHA-1 сертификата, которым подписан APK. Для debug, release и отдельного тестового package нужны соответствующие записи. Публикация в Google Play для установки APK не требуется.
4. В настройках приложения выбрать Google аккаунт и отдельно дать calendar.events разрешение. Это НЕ Firebase email/password, аккаунты могут различаться. Никакие client secrets или пароли Google в приложение не вставляются.
5. Экспорт идёт в primary календарь явно выбранного аккаунта. Выбор других Google календарей пока не реализован, поэтому приложение не запрашивает scope чтения списка календарей.
6. Используется AuthorizationClient с краткоживущим токеном только в памяти; серверный auth code, refresh token и backend для календарей не используются. Отозвать доступ можно кнопкой «Отключить Google» либо в Google Account → Third-party apps.

Что должен сделать пользователь для Яндекса
1. В Яндекс ID → Безопасность → Пароли приложений создать пароль типа «Календарь»: https://id.yandex.ru/security/app-passwords
2. Ввести логин и этот пароль непосредственно в настройках Android-приложения. Не использовать основной пароль аккаунта, не отправлять пароль в чат и не сохранять в репозитории.
3. Нажать «Найти календари» и выбрать доступную коллекцию. Discovery начинается строго с https://caldav.yandex.ru/; HTTPS обязателен, перенаправления запрещены, href проверяется на тот же доверенный host. Пароль не пересылается сторонним адресам.
4. Пароль и привязки хранятся локально в зашифрованном AES-GCM файле noBackupFilesDir; ключ в Android Keystore, отдельный для UID приложения. В Firestore они не отправляются. Ввод пароля не сохраняется через rememberSaveable.
5. «Отключить Яндекс» удаляет локальное подключение. Сам app password надо отозвать в Яндекс ID. Внешние события остаются.

Конфликты и повторные операции
- Внешний ID стабилен для аккаунта/календаря и ID записи; повторный запрос не создаёт случайный дубликат.
- Изменение отправляется с If-Match последней экспортированной версии. HTTP 412/409 показывает конфликт и прекращает запись. Приложение не обновляет ETag перед записью и не затирает внешние изменения автоматически.
- При потере ответа на первое создание можно восстановить связь только если полученная копия совпадает с ранее отправленным содержимым. Консервативное сравнение CalDAV может потребовать ручной проверки, если провайдер преобразовал ICS.
- В этой версии автоматического разрешения конфликтов нет. Если копия снаружи изменена или удалена, это видимая ошибка; новая копия автоматически не создаётся. При утрате локальных привязок изменённая внешняя копия также потребует отдельного решения пользователя.
- Кнопки работают по явному нажатию; очереди внешнего экспорта в фоне нет. Ошибку сети можно повторить. Запросы выполняются на Dispatchers.IO, редиректы/тела ошибок/пароли не логируются.

Проверка
- CalendarExportTest: all-day/multiday/timezone, DST validation, UTF-8 folding и escaping ICS, стабильные ID, POST→PATCH, If-Match конфликты, восстановление потерянного ответа создания, CalDAV discovery/доверенные адреса/XML entities.
- Используются фиктивные transport responses, реальные события этими тестами не создаются.
- Фактические Google OAuth consent, Google Calendar REST и Yandex CalDAV PUT необходимо проверить после подключения владельцем аккаунтов. Без этого нельзя утверждать, что экспорт проверен на реальных календарях.
