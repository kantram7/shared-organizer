[ ] IDEA-002 — Переработать интерфейс и редактирование заметок.
Добавлено: 21.11.2026.
Проблема: текущие заметки неудобны. Особенно неудачны нижние кнопки
«+ список» и «+ заголовок»; этот способ форматирования нужно заменить.

Требования:
- Взять за ориентир привычный дизайн и инструменты работы с текстом
  в готовых приложениях «Заметки».
- Добавить поддержку Markdown.
- Дать возможность выделить текст и применить стиль прямо через меню
  выделения: жирный, подчёркнутый, курсив и другие варианты форматирования.
- Переработать расположение и способ вызова инструментов форматирования,
  чтобы ими было удобно пользоваться при написании заметки.

Перед реализацией выбрать приложение-референс, согласовать макет,
набор стилей и поведение Markdown при редактировании и просмотре.

Исследование приложений от 21.11.2026 (к IDEA-002):

1. NotallyX — ориентир для форматирования выделенного текста.
В контекстном меню есть жирный, курсив, зачёркивание, моноширинный текст,
ссылки и очистка форматирования. Подчёркивание в проверенном меню отсутствует;
для Kotiki оно остаётся отдельным требованием.
Проект: https://github.com/Crustack/NotallyX
Документация: https://github.com/Crustack/NotallyX/blob/main/documentation/docs/features/rich-text.mdx
Реализация меню: https://github.com/Crustack/NotallyX/blob/main/app/src/main/java/com/philkes/notallyx/presentation/activity/note/FormattingActionModeCallback.kt

2. Quillpad — ориентир для Markdown, компоновки и оформления редактора.
В проверенных стилях заголовок редактора использует Inter, размер 20 sp,
жирное начертание; в разметке отступы заголовка и содержимого — 16 dp.
Это параметры референса, а не утверждённые значения для Kotiki.
Проект: https://github.com/quillpad/quillpad
Стили: https://github.com/quillpad/quillpad/blob/master/app/src/main/res/values/styles.xml
Разметка: https://github.com/quillpad/quillpad/blob/master/app/src/main/res/layout/fragment_editor.xml

3. Markor — ориентир для Markdown и настроек чтения/редактирования:
семейство шрифта, размер текста и межстрочный интервал настраиваются отдельно.
Проект: https://github.com/gsantner/markor
Настройки: https://github.com/gsantner/markor/blob/master/app/src/main/java/net/gsantner/markor/model/AppSettings.java

4. Compose Rich Editor — кандидат на основу редактора для Jetpack Compose.
Поддерживает форматирование фрагментов, включая подчёркивание, работу
со списками, импорт и экспорт Markdown/HTML. Меню выделения для Kotiki
нужно настроить отдельно. Совместимость версии с нашим Kotlin/Compose
и сохранность существующих заметок ещё нужно проверить прототипом.
Проект: https://github.com/MohamedRejeb/compose-rich-editor
Стили: https://mohamedrejeb.github.io/compose-rich-editor/span_style/
Markdown: https://mohamedrejeb.github.io/compose-rich-editor/markdown_import_export/

Лицензии проверенных проектов: NotallyX и Quillpad — GPL-3.0;
Markor и Compose Rich Editor — Apache-2.0. Перенос кода и ресурсов должен
учитывать их лицензии; GPL-код нельзя просто объявить частью нашего MIT-кода.
Шрифт Inter доступен отдельно по SIL OFL 1.1 с условиями встраивания:
https://github.com/rsms/inter/blob/master/LICENSE.txt

Предлагаемое направление, пока не утверждено: удобство выделения как
в NotallyX, компоновка с учётом Quillpad, собственное оформление Kotiki,
готовый Compose-редактор после проверки совместимости.
Согласовано: основной формат — Markdown с небольшим расширением <u> для
подчёркивания; отдельный JSON-документ стилей не требуется. Проверить
сохранение оформления при открытии, синхронизации и импорте/экспорте.

Анализ внедрения от 21.11.2026: docs/design/notes-redesign-analysis.txt.
Согласованное направление: компактный визуальный редактор; Markdown как
основной формат текста; настройки чтения отдельно от содержимого.
До выбора движка проверить настоящие чек-листы и выделение между абзацами.
Предусмотреть миграцию старых заметок, правила Firestore и старые очереди,
защиту от конфликтов, последовательное сохранение вне UI-потока.
Реализация и конкретная библиотека пока не утверждены.

Уточнение решения от 21.11.2026: Markdown — источник истины для текста,
визуальный редактор скрывает служебную разметку. Базовый синтаксис Markdown,
чек-листы и зачёркивание из GFM, <u> для подчёркивания. Постоянные параллельные
копии текста в HTML и структурированном JSON не хранить. JSON остаётся
допустимой оболочкой данных и транспорта, а не вторым форматом содержимого.

[ ] IDEA-003 — Общий принцип редактирования текста в приложении.
Добавлено и согласовано направление: 21.11.2026.
Область: заметки, описания планов и задач, сообщения во всех чатах.
Применить общий движок и правила: выделить текст, выбрать стиль в меню,
увидеть оформление; сохранить текст в Markdown. Поддержать ввод Markdown.
Набор инструментов может быть сокращён под конкретное поле, при этом
одинаковые стили и разметка ведут себя одинаково во всём приложении.

Заголовки планов и задач: ограничить набор стилей, чтобы не перегружать
карточки, календарь и списки. Не переносить в заголовок все инструменты
описания. Точный короткий набор определить на макете; начальный вариант
для обсуждения — обычный текст, жирный и курсив без списков, многоуровневых
заголовков, изменения размеров и цветов отдельных слов.

Размеры, шрифт, межстрочный интервал и отступы задаёт оформление приложения
с учётом назначения поля и системного масштаба текста. Личный размер чтения
не изменяет Markdown и вид заметки у другого участника.

Общий редактор не меняет момент сохранения или отправки: описание сохраняется
по сценарию своей формы, сообщение отправляется только явным действием;
сохранение черновика не отправляет сообщение. Права на изменение сообщений
и других записей сохраняются.

Перед внедрением: макеты для разных полей, проверка Markdown/редактора,
совместимости со старыми обычными строками и заметками, серверных правил,
поиска и превью без служебных маркеров. Старый текст с буквальными символами
Markdown не должен автоматически менять смысл. Реализация пока не начата.
Подробности: docs/design/notes-redesign-analysis.txt.

[ ] IDEA-004 — Кнопка возврата к свежим сообщениям в диалоге.
Добавлено: 21.11.2026.
Область: все чаты приложения.
Когда пользователь пролистывает диалог вверх и уходит от свежих сообщений,
показывать в нижнем правом углу полупрозрачную кнопку со стрелкой вниз,
по привычному принципу Telegram. Одно нажатие прокручивает диалог к самым
свежим сообщениям. Когда диалог уже у конца и последние сообщения видны,

непрочитанных сообщений.
Расположить кнопку над полем ввода, чтобы она не перекрывала набор текста
и оставалась доступной при открытой клавиатуре.
Следующий шаг: сначала нарисовать макет и согласовать положение, размер
и прозрачность кнопки. На макете показать прокрутку вверх, конец диалога
без кнопки и состояние с открытой клавиатурой.

[ ] IDEA-010 — Компактное оформление серий сообщений.
Добавлено и согласовано направление: 21.11.2026.
Соседние сообщения одного автора с небольшой паузой группируются визуально:
имя/значок один раз в начале серии, меньше промежутки внутри неё,
более заметное разделение между сериями.

Большая пауза обязательно начинает новую серию даже у того же автора.
Пример пользователя: сообщение сейчас и следующее через 2 часа — разные
серии. Точный порог согласовать по макету; 2 часа — пример, а не утверждённая
граница. Смена автора или дня также разрывает серию. Разделитель
непрочитанного должен оставаться заметным.

Это только визуальная группировка: у каждого сообщения сохраняются
отдельные id, время, состояния отправки, реакции и действия; записи
не склеиваются. Обязательны макеты короткой серии, смены автора и новой
серии после большой паузы. По макету согласовать компактность пузырей,
имя/значок, время и действия. Применить во всех чатах и обсуждениях.

[ ] IDEA-011 — Создание задачи из выделенного текста или меню записи.
Добавлено и согласовано направление: 21.11.2026.
Область: планы, заметки и сообщения во всех чатах и обсуждениях приложения.

Два способа:
1. Выделить текст в плане, заметке или сообщении и выбрать «Создать задачу»
   в меню выделения. Исходный текст новой задачи — именно выбранный фрагмент.
2. Выбрать «Создать задачу» в мини-меню сообщения, плана или заметки:
   - для сообщения взять его текст;
   - для плана взять его заголовок;
   - для заметки взять её заголовок.
   Из меню плана/заметки не подставлять автоматически всё содержимое
   описания/заметки вместо явно указанного пользователем заголовка.

Обязательный сценарий, уточнён пользователем 21.11.2026:
действие «Создать задачу» из выделения или меню всегда открывает существующую
стандартную форму создания задачи с предзаполненным текстом. Это та же форма,
которая используется при обычном создании задачи; отдельная упрощённая
или альтернативная форма не требуется. Все её настройки доступны как обычно.
Задача создаётся только после явного сохранения формы. Отмена формы
не создаёт задачу. Источник остаётся самостоятельной записью.
Длинный или многострочный исходный текст не должен теряться при ограничении
длины названия: сохранить полный текст в описании, способ короткого названия
уточнить на макете. Проверить извлечение видимого текста из Markdown,
чтобы служебные маркеры не превращались в мусор в названии задачи.

Создание доступно из читаемого пользователем содержимого, в том числе
из входящего сообщения, без необходимости права редактировать оригинал.
Личный исходный текст не должен автоматически публиковаться как общая задача;
видимость новой задачи должна быть понятна до сохранения.

Внутренняя ссылка на источник — согласовано и уточнено 21.11.2026.
Ссылку добавлять обычной строкой в описание задачи при предзаполнении
стандартной формы. Отдельную кнопку или отдельный блок для источника
не добавлять. Пример строки:
Из сообщения: kotiki://chat/<chatId>/message/<messageId>
Для других источников — «Из заметки: ...» и «Из плана: ...» с соответствующим
внутренним адресом. Строка должна быть кликабельной в просмотре описания.
Оформление обычной текстовой/Markdown-ссылки согласовать на макете.

Это адрес конкретного исходного объекта, в том числе при создании задачи
из выделенного фрагмента текста:
- сообщение: открыть исходный чат, подгрузить нужную часть истории,
  прокрутить к реплике и кратко подсветить её;
- заметка: открыть конкретную исходную заметку;
- план: открыть конкретный исходный план, а не только тему.

Внутренний адрес содержит тип и устойчивые идентификаторы объекта,
для сообщения также контекст чата; при реализации учитывать пространство
и профиль. Источник не искать по скопированному тексту или названию.
Переименование источника не должно ломать переход. Ссылка вместе с текстом
описания сохраняется только после подтверждения стандартной формы;
отмена формы ничего не создаёт.

Удаление сообщения:
- Текущая модель чата сохраняет id и отметку deleted, очищая текст.
- Если исходное сообщение удалено, но его заглушка доступна, переходить
  к заглушке «Сообщение удалено» в соответствующем чате.
- Задача и перенесённый в неё пользователем текст остаются самостоятельными
  данными; удаление оригинала их автоматически не удаляет и не изменяет.
- Не восстанавливать удалённый текст оригинала в чате или предпросмотре
  ссылки из копии, оставшейся в задаче.

Переход соблюдает текущие права доступа. Личная заметка/закрытый контекст
не становятся общими через ссылку; без доступа не раскрывать название
или содержимое источника. Если чат/запись целиком удалены или доступ потерян,
показать «Источник недоступен», сохранив задачу. Отсутствие соединения
или незавершённая загрузка не означают, что источник удалён: показать
соответствующее состояние и дать повторить загрузку.

Макеты: пункт в меню выделения, пункт в мини-меню источника, стандартная
предзаполненная форма и строка внутренней ссылки в описании задачи.
Более широкую структуру связей «план — задачи — заметки» определить отдельно.

ИСПРАВЛЕНИЯ

[ ] FIX-001 — Равномерные внутренние отступы кнопок в планах.
Добавлено: 21.11.2026.
Проблема: после названия на кнопке остаётся лишнее пустое место.
Требование: граница должна иметь одинаковый внутренний отступ вокруг текста,
без избыточного пустого пространства после названия. Проверить короткие
и длинные названия.

[ ] FIX-002 — Высота прямоугольников недель в календаре по содержимому.
Добавлено: 21.11.2026.
Проблема: одинаковая высота всех недель оставляет много пустого места под
числами в неделях без точек событий; недели с точками выглядят нормально.
Требование: недели могут иметь разную высоту в зависимости от индикаторов
событий, сохраняя выравнивание дней внутри одной недели.
Следующий шаг: сначала нарисовать макет и вместе оценить варианты высоты
на неделях без событий, с точками и с многодневными событиями; после этого
согласовать итоговое отображение и внедрение.

[ ] FIX-003 — Положение и толщина полосы многодневного события в календаре.
Добавлено: 21.11.2026.
Проблема: сейчас многодневное событие выглядит как толстая линия слишком
низко под числом — ниже точек событий и границ выделения текущей даты.
Предлагаемое отображение: расположить полосу сразу под рядом точек, сделать
её толщину соответствующей диаметру точек и поместить внутри области
выделения текущей даты, чтобы она не уходила ниже её границ.
Следующий шаг: сначала нарисовать макет и оценить его вместе с FIX-002.
На макете проверить сочетание точек и полосы, текущую и выбранную даты,
а также продолжение многодневного события на следующей неделе. Итоговое
расположение и толщину согласовать по макету перед внедрением.

[ ] FIX-004 — Прокрутка диалога к последнему сообщению при фокусе ввода.
Добавлено: 21.11.2026.
Область: все чаты приложения.
Проблема: при установке курсора в поле сообщения открывается клавиатура,
которая закрывает нижнюю часть диалога. До последних сообщений приходится
дополнительно прокручивать пальцем.
Требование: при переходе фокуса в поле ввода автоматически прокрутить диалог
до самого свежего сообщения с учётом появившейся клавиатуры и новой высоты
видимой области. Последнее сообщение должно быть доступно над полем ввода,
без ручной прокрутки. Прокрутка до изменения размеров экрана не должна
оставлять сообщения за клавиатурой.
Проверить первый и повторный фокус, открытие клавиатуры после её скрытия,
короткий и длинный диалог, многострочное поле ввода и согласованную работу
с кнопкой возврата вниз из IDEA-004.

[ ] FIX-005 — Широкое поле сообщения с круглой кнопкой отправки внутри.
Добавлено: 21.11.2026.
Область: поля ввода сообщений во всех чатах приложения.
Убрать отдельную текстовую кнопку «Отправить» справа от поля и расширить
поле ввода на освободившееся место.

Новая кнопка: круглая, с понятной эмблемой стрелки вверх, которая считывается
как отправка сообщения. Расположить её внутри правой части поля ввода.
По последнему уточнению пользователя кнопка видна постоянно: при пустом
поле она бледная, при появлении хотя бы одного символа — обычной яркости.
После очистки текста кнопка снова бледнеет и остаётся на месте.
Пустое сообщение не отправляется. Проверка допустимости текста выполняется
отдельно от изменения яркости кнопки.

Когда длинное сообщение увеличивает высоту поля, кнопка остаётся в правом
верхнем углу внутри поля. Под неё зарезервировано место: текст и курсор
не перекрываются с кнопкой. Резерв должен выглядеть естественно и незаметно,
без отдельной рамки, плашки или бросающегося в глаза пустого блока.
Ширина поля и расположение кнопки не меняются при смене её яркости.

Следующий шаг: нарисовать макет поля и значка стрелки. Показать пустое поле
с бледной кнопкой, поле с одним символом и длинное многострочное сообщение;
проверить понятность отправки и совместное расположение с кнопкой возврата
вниз из IDEA-004. Вариант отправки изображения без подписи отдельно
согласовать в IDEA-005, где реализация пока не определена.

[ ] FIX-006 — Новые входящие не уводят из читаемой истории.
Добавлено и согласовано: 21.11.2026.
При чтении старых сообщений новое входящее не прокручивает диалог вниз.
Сохранять место чтения; индикацию новых сообщений и явный возврат к ним
связать со стрелкой из IDEA-004. Автопрокрутка входящих допустима, когда
пользователь уже у конца. Подгрузка истории тоже сохраняет видимый фрагмент.
Прокрутку при фокусе поля/клавиатуре из FIX-004 сохранить как отдельный
явный сценарий. Применить во всех чатах и обсуждениях.

[ ] FIX-007 — Ошибка и повтор отправки у конкретного сообщения.
Добавлено и согласовано: 21.11.2026.
Приоритет: обязательно.
У исходящего сообщения понятны ожидание, подтверждённая отправка и ошибка.
При ошибке есть повтор у конкретного сообщения; введённый текст не теряется.
Повтор использует тот же id, без дублей при повторных нажатиях
и восстановлении соединения. Подтверждение сервером не выдавать за доставку
на телефон или прочтение другим участником. Применить во всех чатах.

[ ] FIX-008 — Метка «изменено» у отредактированного сообщения.
Добавлено и согласовано: 21.11.2026.
Показывать компактную метку возле времени. Сохранить текущие права
на редактирование. Полная история редакций этим пунктом не добавляется.
Применить во всех чатах и обсуждениях.

[ ] FIX-009 — Статус синхронизации чата только по необходимости.
Добавлено и согласовано: 21.11.2026.
В обычном успешном состоянии строка «Сообщения синхронизированы»
не занимает место над перепиской. Ошибки, отсутствие соединения и ожидание
остаются заметными. Общий статус и состояние отдельной отправки
не должны дублироваться без необходимости. Применить во всех чатах.

[ ] FIX-010 — Сворачиваемое описание в обсуждении плана.
Добавлено и согласовано: 21.11.2026.
Описание можно раскрыть/свернуть, сохраняя доступ к контексту. Оно не должно
вытеснять переписку при открытой клавиатуре. Проверить оба состояния
на макете. Аналогичные большие блоки контекста в других обсуждениях
должны соблюдать тот же принцип.
