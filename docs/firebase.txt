Firebase — вход, доступ и синхронизация (0.3.0)

Что работает
- Вход по email/паролю через Firebase Authentication; пароли не сохраняются кодом приложения.
- Допуск к одному пространству только для двух UID, заданных администратором. Установка APK и произвольная регистрация в Firebase сами по себе доступа не дают.
- Приложение слушает доступные записи Firestore; Android SDK хранит локальный кэш и очередь записей без сети.
- Текущее состояние и новая неизменяемая версия записываются одним batch. Побеждает последняя запись, принятая сервером, а не часы телефона. Все успешно принятые изменения остаются в revisions.
- Общие записи доступны обоим. Личные доступны только владельцу. Для «Занято» отдельная проекция содержит только расписание, без названия и комментария. Видимость выбирается при создании и затем неизменна: правила запрещают переходы между SHARED, PRIVATE и BUSY, а также изменение общей/личной видимости списков.
- Удаление сохраняет tombstone и историю. Физическое удаление документов с клиента запрещено.
- Получатель может принять приглашение, отказаться или предложить изменения. Встречное предложение подтверждает другой участник. До подтверждения переноса принятой встречи остаётся прежнее расписание. Устаревшие ответы на заменённое предложение отклоняются сервером.
- Демо открывается отдельно и автоматически не переносится в облако. Личные debug-пресеты никогда не используются как облачная авторизация.

Границы этапа
Push доставляются отдельным Cloudflare Worker через FCM; локальные напоминания, PIN/биометрия и предложения изменения приглашений реализованы. Кнопки Google/Яндекс Календаря требуют отдельных подключений и реальной проверки владельцем. Старое локальное демо автоматически не импортируется.
Права на сервере не могут стереть сведения, которые другой участник уже прочитал или сохранил на своём устройстве. Офлайн-кэш может содержать ранее доступные записи до обновления с сервера.
История сохраняется для каждой записи; в интерфейсе событий/дел показываются последние 30 доступных версий. Для списков и планов версии также сохраняются в базе; отдельный просмотр в интерфейсе пока не добавлен.
После отклонённой сервером записи её копия остаётся в локальном хранилище текущего аккаунта (failed_<recordId>); приложение показывает ошибку. Автоматически повторно публиковать такие изменения нельзя.
Выход из аккаунта недоступен, пока есть ожидающие отправки записи.

Развёртывание
1. Создать Firebase-проект и Android-приложение team.kotiki.app. Поместить google-services.json в android/app/ (он игнорируется Git).
2. Включить Email/Password и создать два аккаунта в Authentication. Пароли вводятся владельцами аккаунтов самостоятельно.
3. Установить Firebase CLI 15.36.0, firebase 13.4.0 и @firebase/rules-unit-testing 6.0.0 вне репозитория, используя Node 24. Для локального Firestore Emulator нужен JDK 21.
4. Выполнить firebase login. Авторизация CLI хранится штатным механизмом Firebase вне репозитория; для начальной настройки ключ service account не нужен. Отдельный минимальный служебный аккаунт для push описан в backend/push/README.txt.
5. Создать игнорируемый private/firebase/workspace.json по backend/workspace.example.json. Указать точные UID, роли, отображаемые имена, ID проекта и пространства.
6. KOTIKI_FIREBASE_TOOLS указывает на внешний каталог, содержащий node_modules/firebase-tools, node_modules/firebase и node_modules/@firebase/rules-unit-testing.
7. node backend/setup.cjs enable private/firebase/workspace.json
8. firebase firestore:databases:create "(default)" --project <project-id> --location <chosen-region> --edition standard --delete-protection ENABLED --point-in-time-recovery DISABLED
   Регион выбирается до создания и затем не изменяется. Не создавать вторую базу вместо уже существующей.
9. Сначала выполнить тесты правил (testing/firebase/README.txt). Затем firebase deploy --only firestore:rules,firestore:indexes --project <project-id>.
10. node backend/setup.cjs bootstrap private/firebase/workspace.json
    Скрипт проверяет существование обоих Auth-пользователей, создаёт одну запись пространства и две привязки. Уже существующие несовпадающие записи не перезаписывает.

Структура базы
members/{uid}: spaceId. Только собственное чтение; запись только администратором.
spaces/{spaceId}: uids (ровно два), roles (UID → USER_1/USER_2), names (роль → имя). Чтение участниками, запись только администратором.
spaces/{spaceId}/records/{type_id}: type, owner UID, readers, shared, data, deleted, revision, updatedAt server timestamp, actor UID.
spaces/{spaceId}/records/{type_id}/revisions/{revision}: неизменяемый полный снимок. Чтение требует текущего доступа к записи и доступа к самой версии.
spaces/{spaceId}/busy/{entry_id}: разрешённое расписание при active=true. Неактивный документ доступен только владельцу; он не содержит расписания.

Чаты
Общий текстовый чат находится между «Зовут» и «Общий сбор». У каждого отдельного плана и общей задачи/события есть собственное обсуждение.
spaces/{spaceId}/chats/{chatId}: неизменяемые type, collectionId, itemId, createdBy, createdAt.
Вложенные messages: sender (канонический участник), actor (фактический Auth UID), role, text, createdAt, clientTime, deleted.
Чат показывает последние 100 сообщений, до 4000 символов в одном. Удаление своего сообщения оставляет отметку; переписывание чужого текста запрещено.
Удаление плана или записи закрывает чтение и отправку его обсуждения. Вложения и поиск отсутствуют. Push чатов доставляются отдельным Cloudflare Worker через FCM; настройка в backend/push/README.txt.
Для выбранных тестовых аккаунтов администратор может назначить временную роль: members содержит canonicalUid и expiresAt. Общего доступа для анонимов нет. История сохраняет фактический UID агента.

Уведомления 0.3.0
spaces/{spaceId}/devices/{authUid_installation}: фактический UID, канонический UID, FCM-токен, время регистрации. Читать и удалять может только тот же Auth UID; повторное удаление своей отсутствующей регистрации разрешено для безопасного выхода.
spaces/{spaceId}/pushQueue/{revisionOrMessageId}: kind, recordId, revision, chatId, messageId, actor, createdAt. Клиент создаёт событие только атомарно с соответствующей записью/сообщением; чтение, изменение и удаление ему запрещены.
Настраиваемая локальная блокировка PIN/биометрией не заменяет Firebase-аутентификацию и серверные права.
