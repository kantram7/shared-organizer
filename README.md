# shared-organizer

A shared organizer for two: tasks, plans, lists, and calendar.

Совместный органайзер для двоих. Название приложения на телефоне — **Kotiki team**.

## Текущая версия

`0.2.1` — Android-приложение с входом через Firebase, общим пространством и отдельным локальным демо. Основа — нативный Android-прототип на Kotlin и Jetpack Compose с обезличенными участниками «Пользователь 1» и «Пользователь 2».

- Общий текстовый чат и отдельное обсуждение каждого плана. Собственные сообщения можно удалить; черновики и очередь отправки сохраняются локально.
- Доска: основной вертикальный обзор недели и подробная лента дней. Режим запоминается; неделя, фильтр и положение ленты сохраняются при переходах между разделами.
- Темы планов и списки: до двух строк плиток, остальные в «Ещё»; «Развернуть / Свернуть» показывает или скрывает все группы. Планы только общие. Сортировка по изменениям обновляется при входе в раздел. Списки сохраняют общую и личную видимость.
- Удаление записей и пунктов с отменой; удаление тем и списков с подтверждением и отменой. Частные демотемы планов удаляются при обновлении до этой версии.
- Месячный календарь с многодневными полосами без названий; подробности в выбранном дне. Смена месяца намеренно сохраняет выбранную дату.
- Редактор с закреплённым сохранением, сохранением черновика при пересоздании Activity, значками видимости и пояснениями по нажатию.
- Портретная ориентация на телефоне; при крупном шрифте боковая панель заменяется раскрываемым меню. Настройки закреплены внизу навигации.
- Приглашения, история и архив. Входящее приглашение можно принять на доске, в календаре, разделе «Зовут» или подробностях. В облачном режиме ответ передаётся второму участнику; принять за автора нельзя. В локальном демо ответ сохраняется на телефоне с возможностью отмены. «Общий сбор» — отдельное событие-приглашение для обоих участников с обязательными датой и временем, сердечком и отдельным оттенком карточки. Push-уведомления пока не подключены; доступен ручной локальный пример уведомления.
- Светлая/тёмная тема и сохранение данных на устройстве.
- Дни обзора разделены рамками; при первом открытии текущая дата сразу видна. Управление неделей остаётся над прокруткой.
- Фирменный знак в шапке, эмблема с надписью при запуске, адаптивная векторная иконка Android.

Без локального пресета демо использует профиль «Пользователь 1». Для личной отладочной сборки предусмотрен игнорируемый пресет — [инструкция](testing/README.txt). Демо и облачные данные разделены: демонстрационные записи автоматически не загружаются в Firebase.

## Firebase

При наличии локального `android/app/google-services.json` приложение показывает вход по email/паролю. Аккаунт допускается только после привязки администратором к пространству с двумя участниками. Общие записи синхронизируются, личные защищены серверными правилами, для скрытых подробностей передаётся отдельная проекция занятости. Каждое изменение сохраняется вместе с неизменяемой версией; при конфликте побеждает последняя запись, принятая сервером.

[Настройка, модель доступа и ограничения](docs/firebase.txt). [Тесты правил](testing/firebase/README.txt). Без конфигурации Firebase доступно локальное демо.

Идентификатор приложения — `team.kotiki.app`; прежнее `team.kotiki.app.demo` устанавливается отдельно, его локальные данные автоматически не переносятся. Используются Firebase Authentication и Firestore; Analytics не подключён. Ключи администратора не входят в приложение.

PIN/биометрия, push-уведомления, встречные предложения по приглашениям, импорт старых демоданных и интеграции с Google/Яндекс Календарём пока не реализованы.

## Сборка

Нужны JDK 21, Android SDK Platform 36 и Build Tools 35.0.0. Gradle 8.13 закреплён в Wrapper; Android Gradle Plugin — 8.13.2. Полный набор версий и источники описаны в [BUILD-NOTES.txt](docs/BUILD-NOTES.txt).

1. Укажите JDK в `JAVA_HOME`.
2. Укажите Android SDK в `ANDROID_HOME` или в локальном `local.properties` через `sdk.dir`. Этот файл исключён из Git.
3. В корне репозитория выполните:

```powershell
.\gradlew.bat assembleDebug testDebugUnitTest lintDebug
```

На macOS/Linux: `sh ./gradlew assembleDebug testDebugUnitTest lintDebug`.

При первом запуске загружаются Gradle и зависимости. Для Maven Central настроено дополнительное HTTPS-зеркало Google. APK появится в `android/app/build/outputs/apk/debug/app-debug.apk`. Минимальная версия Android — 9 (API 28), целевая — API 36.

В Windows также доступен `build-local.ps1`: по умолчанию он выполняет те же три проверки. Для отдельного набора инструментов передайте `-ToolRoot <путь>`; в нём ожидаются `java/<JDK>`, `android-sdk` и `gradle-8.13`. Параметр `-RuntimeRoot <путь>` выносит результаты сборки, тестовые данные и кэши проекта за пределы репозитория. Без него используется игнорируемая `.local/`.

Локальные пути можно один раз записать в игнорируемый `build.local.json` с полями `toolRoot` и `runtimeRoot`. Параметры командной строки имеют приоритет. Скрипт восстанавливает переменные окружения после завершения. При таком запуске APK находится в `<RuntimeRoot>/build/app/outputs/apk/debug/app-debug.apk`, а отчёты — в `<RuntimeRoot>/build/app/reports/`.

## Подпись APK

По умолчанию Android Gradle Plugin создаёт локальный ключ отладки. Для обновления уже установленной демоверсии нужен тот же ключ, которым она была подписана.

При наличии сохранённого ключа задайте переменные окружения `KOTIKI_DEBUG_KEYSTORE` (абсолютный путь), `KOTIKI_DEBUG_STORE_PASSWORD`, `KOTIKI_DEBUG_KEY_ALIAS` и `KOTIKI_DEBUG_KEY_PASSWORD`. Значения не храните в репозитории. Если ключ отличается, Android не установит APK поверх старого: потребуется старая подпись либо удаление предыдущего приложения с потерей его локальных данных.

## Проверки

В Android-модуле 37 автоматических тестов (в том числе 5 проверок облачного хранилища): 12 тестов модели, 6 тестов хранилища, 6 UI-тестов, 5 тестов общего сбора и 3 теста принятия приглашений. Проверяются обязательное расписание, постоянные участники, сохранение типа записи, отдельный канал уведомлений, скрытие подробностей на экране блокировки и переход к нужному приглашению. UI-тесты выполняются в Robolectric на API 35. Отчёты находятся в `android/app/build/reports/`.

На реальных телефонах нужно проверить:

1. Прокрутку дней и переключение недель, фильтры участников.
2. Создание дела на день и без дня, выполнение и возврат в работу.
3. Закрытие редактора крестиком без сохранения, работу клавиатуры.
4. Значки видимости и подсказки, замок приватности.
5. Добавление группы планов, списка и пунктов.
6. Многодневные события в календаре.
7. Сохранение записей и темы после перезапуска.
8. Фиксацию портретной ориентации и адаптивное меню при увеличенном системном шрифте.

Для ручной проверки используются два физических Android-устройства; их конкретные модели хранятся только в локальном плане тестирования. Успех автоматических проверок не означает, что приложение уже проверено на этих устройствах.

## Состав репозитория

В корне остаются Gradle Wrapper, конфигурация сборки, лицензия и краткая документация. Материалы разделены:

- `android/app/` — код Android-приложения, манифест и стили; адаптер векторных иконок в `ui/icons/`.
- `graphics/` — векторные ресурсы и HTML-макет.
- `backend/` — правила Firestore и однократная настройка пространства; `firebase.json` — конфигурация развёртывания и эмуляторов.
- `testing/` — тесты, управление эмуляторами, обезличенный шаблон пресета и инструкции.
- `testing/local/` — игнорируемые личные пресеты, отчёты и снимки.
- `docs/` — требования и описание сборки.
- `private/` — игнорируемый личный контекст разработчика.

Документы проекта:

- [Утверждённое ТЗ v1](docs/spec-v1.txt) — полные требования, включая будущие функции.
- [Макет v1](graphics/mockups/mockup-v1.html) — сохранённый интерактивный HTML-прототип интерфейса; Android-приложение реализуется отдельно.

SDK, кэши, APK, закрытые ключи и локальные настройки сервисов исключены через `.gitignore`.

Личные настройки и сопоставления участников не публикуются. При обновлении раннего приватного прототипа локальная сборка может получить каталог `KOTIKI_MIGRATION_ASSETS` с файлом `legacy-roles.json`: объект JSON сопоставляет прежние коды участников с `USER_1` и `USER_2`. Новые записи сохраняются с обезличенными кодами. В обычной публичной сборке этого файла нет; для обновления старого приватного прототипа используйте локальную сборку с соответствующим сопоставлением.

## Личный контекст разработчика

Рядом с кодом можно хранить локальный файл `private/PERSONAL-CONTEXT.txt`. Папка `private/` исключена из Git. Для новой рабочей копии используйте [обезличенный шаблон](docs/personal-context.example.txt).

В нём указываются соответствие «Пользователь 1 / Пользователь 2» реальным участникам, модели и версии тестовых устройств, часовой пояс, личные предпочтения и пути к локальному окружению. Приложение не читает этот текст автоматически.

Пароли, токены и содержимое ключей в контекст не помещаются: допустимы только ссылки на отдельное локальное хранилище. Ключи подписи, SDK и резервные копии остаются вне папки кода.

Правила работы с контекстом для агента записаны в [AGENTS.md](AGENTS.md). Перед коммитом проверяйте список файлов и diff: `.gitignore` не удаляет сведения из уже опубликованной истории и не исключает файлы, которые ранее были добавлены в Git.
